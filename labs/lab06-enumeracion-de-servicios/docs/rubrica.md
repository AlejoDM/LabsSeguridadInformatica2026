## Parte práctica (20)
4 pts por flag, con captura de `./ctf status 06`.

## Inventario de enumeración (40)

| Puntos | Descriptor |
|---:|---|
| 36–40 | Los 5 hallazgos documentados con **técnica**, **evidencia** (salida real) y **riesgo fundamentado**. Explica qué habilita cada uno para la explotación (Lab 07). |
| 28–35 | Hallazgos con evidencia pero el riesgo o el "qué habilita" es genérico. |
| 20–27 | Lista hallazgos sin evidencia o sin conectar con la fase siguiente. |
| 10–19 | Pega salidas de tools sin analizar. |
| 0–9 | Ausente o incorrecto. |

**Rechazo del componente:** presentar como propio un hallazgo copiado del
`solucion.md`, o afirmar un riesgo sin evidencia que lo respalde.

## Preguntas P1–P5 (25)
5 pts cada una. Se evalúa precisión y uso de evidencia del lab. Ojo P2 (.git) y
P4 (por qué enumerar usuarios importa para la fase siguiente).

## Mini-research (10) · Proceso Git (5)
Igual que labs anteriores. Commits de una sola cuenta = no entregado por el grupo.

## Causales de rechazo del trabajo
1. Enumerar cualquier sistema que no sea el target de la cátedra (Ley 26.388).
2. Flags obtenidas leyendo el código del target o el solucion.md.
3. Uso de IA no declarado.
